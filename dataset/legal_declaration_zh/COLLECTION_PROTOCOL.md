# legal_declaration_zh 探针集·人类侧收集协议

**版本**: v1.0（2026-08-17）
**目的**: 为W5探针集收集人类侧≥60篇（目标60-80）真实公文，与AI侧320篇（`dataset/paired_generation_v1/`，3模型×2臂×60主题）构成**同语域对照基线**。
**关联**: `.sisyphus/plans/fn1-countermeasures-and-paired-experiment.md` W5；`docs/research/2026-08-fn1-root-cause-and-contract-duality.md`（为何同语域是生死线）

## 0. 黄金律：双侧同语域

探针集的唯一使命是回答："**在同一语域内**，检测器能否区分人类与AI？"

因此人类侧文档类型必须映射AI侧主题清单（声明/承诺书/情况说明/公告[更正/致歉/澄清/召回/维护/变更]/通报/合规文件）。任何语域外文本都会把"语域差异"混入"作者身份"信号，制造HC3式捷径（FN-1根因第二层），使基线虚高或虚低。

**排除清单（用户常见候选及其排除理由）**：

| 来源 | 排除理由 |
|---|---|
| GitHub代码/Issue | 技术语域+英文为主，与公文零重叠 |
| 技术文档（docs） | 说明文语域，句式结构与公文不同 |
| 论文（arXiv/CNKI） | 学术语域；引用/术语密度是另一分布 |
| 新闻报道 | 新闻是**关于公文的转述**（导语/引语结构），不是公文本身；仅新闻网站**全文转载的公告原文**可作Tier B fallback（记录转载源） |
| 文学作品 | 创作语域，与公文差异最大 |
| Wikipedia/百科 | 说明文语域 |
| 公文模板（未填空） | 是骨架不是成文；无作者身份可言 |

## 1. 来源分层（Tier）

### Tier A — 监管与政务公开（目标~15篇）

| 来源 | 检索入口 | 类型 |
|---|---|---|
| 市场监管总局及地方局 | samr.gov.cn（公告栏目） | 监管公告、召回公告 |
| 缺陷产品召回中心 | samrdprc.org.cn | 企业召回公告（原文） |
| 网信办/地方网信 | cac.gov.cn | 网络安全审查公告等 |
| 政府门户信息公开栏 | 各省市门户"政府信息公开" | 政务承诺书、情况通报、问责通报 |
| 司法局/律师协会官网 | sfj.*.gov.cn、律协官网 | 严正声明（淄博模式） |

**优势**：著作权法第5条——国家机关决议/决定/命令等官方文件不适用著作权保护，license最干净；URL稳定；日期权威。

### Tier B — 上市公司信息披露（目标~40篇，主力）

| 来源 | 检索入口 | 类型 |
|---|---|---|
| 巨潮资讯网（cninfo，官方指定平台） | 按"公告类型"检索：更正公告/致歉公告/澄清公告/承诺函/情况说明 | 与AI侧doc_type一一对应 |
| 沪/深/北交易所披露平台 | sse.com.cn / szse.cn / bse.cn | 同上（原文PDF） |

**优势**：类型标签结构化可检索、数量充足、PDF原件带发布日期可溯源。
**注意**：`License note = 上市公司公开披露信息`；记录公告ID与PDF哈希。

### Tier C — 机构官方声明（目标~15-25篇）

| 来源 | 类型 |
|---|---|
| 高校官网公告/新闻栏（武大/上大模式） | 情况通报、情况说明 |
| 银行/券商官网公告栏 | 系统维护/升级公告 |
| 医院官网 | 情况说明、致歉声明 |
| 行业协会（足协/消协/律协） | 严正声明、情况说明 |
| 企业官网/IR页 | 致歉声明、召回公告、澄清声明 |

**注意**：逐站抓取，URL稳定性中等，`fetch_date`必填；无法验证官方性的（如自媒体转载）排除。

## 2. 收集标准

### 2.1 硬标准（一票否决）

| # | 标准 | 判定方法 |
|---|---|---|
| H1 | **语域匹配**：doc_type落在AI侧类型清单内 | 对照§3配额矩阵；`detect_register_zh()`自动门（得分≥6）+人工抽检 |
| H2 | **人类作者身份可验证·时间锚定**：发布日期**早于2023-01-01**（占全集≥70%），或2023年后但发布主体为官方披露流程（如交易所强制披露，`era=post2023`标记） | 元数据`published_date`+来源页面日期证据 |
| H3 | **文本完整性**：标题→落款全文，非节选/转述/摘要 | 提取后人工过目；PDF页码噪声可清理，正文逐字 |
| H4 | **可溯源**：source_url/publisher/published_date/fetch_date/doc_type/license_note/sha256(text)七元组完整；PDF原件归档`_pdfs/` | 入库脚本强制字段 |
| H5 | **去重**：sha256精确去重 + 5-gram Jaccard>0.8近似去重（跨源转载） | 入库脚本自动 |
| H6 | **非模板填表**：排除系统自动生成的填表式公告（如<200字的减持进展类纯填空公告）——它们是"机器生成但非LLM"的第三类文本，会污染人机对照 | 长度+结构启发式+人工抽检 |

### 2.2 软标准（配额控制）

| # | 维度 | 控制 |
|---|---|---|
| S1 | doc_type多样性 | 按§3矩阵配额，单一类型≤20% |
| S2 | 来源分层 | Tier A/B/C ≈ 15/40/20±5，单一发布主体≤3篇 |
| S3 | 时间分布 | pre-2023 ≥70%；其余`era`字段标记 |
| S4 | 长度分布 | 短(300-600)/中(600-1200)/长(1200-2000) ≈ 各1/3；超2000的完整通报保留并标记`overlen`（完整性优先于长度控制） |
| S5 | 主题多样 | 单一行业/事件簇≤10%；同一事件的"更正前+更正后"自然对可保留（标记`event_pair`） |

## 4. 入库管线

```
抓取（web-reader/PDF下载）
  → 元数据七元组 + PDF归档
  → 正文提取（HTML清理导航广告 / pypdf提取，仅去非正文元素与页码）
  → H4强制字段校验 + sha256
  → H5去重（精确+5-gram）
  → H1语域自动门（detect_register_zh ≥ 6；不达标→人工复核→排除并记录原因）
  → H6模板填表排除（人工抽检全部<300字样本 + 疑似列表）
  → 抽检10%人工过目（语域/完整性/era证据）
  → 入库 dataset/legal_declaration_zh/human/NN-type-slug.md（沿用试批格式）
  → 重跑 scripts/eval_human_probe.py → scripts/defensibility_report.py（正式版计分卡）
```

**每篇排除都要记录**`excluded.jsonl`（file/reason/code），保证收集过程可审计——这本身就是D判据精神。

## 5. 验收标准

| 项 | 门槛 |
|---|---|
| 数量 | ≥60（目标70）；双侧元数据完整率100% |
| H2时间锚定 | pre-2023占比≥70% |
| 配额 | 矩阵覆盖率≥80%；单类型≤20%；单主体≤3篇 |
| 去重 | 零精确重复；零5-gram>0.8近似对 |
| 语域门 | 自动门通过率≥90%（不通过的记录人工复核结论） |
| 抽检 | 10%人工抽检：语域/完整性/era证据三项全过 |
| 产出 | 正式基线报告（AUROC/FPR@5%@Wilson区间/四阶段分解，替代PRELIMINARY计分卡） |

## 6. 与AI侧的匹配度检查（入库后）

1. 长度分布对比（KS检验或分位数目测，AI侧中位数 vs 人类侧）
2. register_score分布对比（两侧都过语域门后分数应同区间）
3. doc_type覆盖率对照（AI侧60主题的type清单 vs 人类侧矩阵）
4. 不匹配项报告并调整（人类侧补收，**不裁剪AI侧**——AI侧是实验产物）

## 7. 已知限制（诚实登记）

- **2023后公文无法100%排除AI辅助**：官方披露流程（交易所审核+公司签署）是强旁证但非证明；`era`字段保留区分，基线报告可按era分层输出
- **公文语域内部仍有子风格差**（监管公告vs公司公告vs高校通报）：矩阵控制类型占比即为此；基线报告按doc_type分桶
- **人类侧无"合约约束生成"对照**：人类写公文本就受格式约束（这正是坍塌的原因），两侧约束来源不同（社会规范vs提示词）——这是语域本质，不是可消除的混杂
