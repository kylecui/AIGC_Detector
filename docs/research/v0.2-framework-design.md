## 2. 核心抽象：DetectionPlan（一份YAML声明一切）

```yaml
# plans/default.yaml —— 一个"检测计划"=框架的完整部署单元
plan: default@v0.2
stages:                      # 可插拔检测agent（每个实现Stage契约）
  - id: statistical
    impl: aigc_detector.detection.statistical:StatisticalStage
    per_language: {zh: IDEA-CCNL/Wenzhong-GPT2-110M, en: openai-community/gpt2-xl}
  - id: encoder
    impl: aigc_detector.detection.encoder:EncoderStage
    adapter: models/encoder-{lang}          # 引用而非内联
  - id: binoculars
    impl: aigc_detector.detection.binoculars:BinocularsStage
    pairs: {zh: [Qwen/Qwen2-7B, Qwen/Qwen2-7B-Instruct], en: [tiiuae/falcon-7b, ...]}
routing:                     # 语言×语域 → 权重与阶段集
  default: {zh: {encoder: .60, binoculars: .20, statistical: .10, linguistic: .10},
            en: {linguistic: .85, statistical: .15}}
gates:                       # 声明式门控（现在是代码里的词表）
  - id: formal_zh
    impl: lexical
    markers: configs/gates/formal_zh_markers.yaml   # 词表出代码进config
    threshold: 6
    on_hit: [caveat, calibrate, floor]
  - id: formal_en
    impl: lexical+ml
    ml_artifact: models/calibration/en_register_gate
    on_hit: downgrade        # 置信封顶0.49（W16行为声明化）
calibration:
  - artifact: models/calibration/global_temperature.json   # 含enablement条件
  - artifact: models/calibration/binoculars_floor.json
policy:                      # 决策后处理规则（现在是routes里的函数）
  - when: gate(formal_zh) and binoculars >= 0.46
    then: upgrade_ai_verdict with provenance        # W15 OR规则
  - when: gate(formal_en)
    then: cap_confidence 0.49 with warning
probes:                      # 验收探针（verify门的声明化）
  - id: fn1-known-bad
    fixture: tests/fixtures/fn1_declaration.txt
    asserts: {max_segment_p_ai: ">=0.8", verdict_unchanged: true}
  - id: human-probe-zh
    dataset: dataset/legal_declaration_zh/human
    asserts: {fpr_upper_wilson95: "<= 0.31"}
verify:                      # 发布断言（现在在verify_release.ps1里的硬编码）
  - tests_pass: true
  - ruff_clean: true
  - wheel_selfcontained: [static, configs]
```

**一份Plan = 完整可审计的部署描述**。审稿人/采购官/复现者读一份YAML即知系统全貌——这是论文artifact与产品config的同构。

## 3. 四个运行时组件

1. **PlanRunner**：唯一装配点（消灭main.py/build_pipeline双写）——加载Plan→实例化stages/gates→构建Pipeline。API lifespan与实验脚本全部改为`PlanRunner.load("plans/default.yaml")`
2. **Stage契约**：统一接口（现有四个检测器方法签名已接近，需归一）——第三方可写新stage（如水印检测agent、检索agent）插入
3. **GateKit**：词法/ML/规则门实现+词表外置yaml——门控行为从代码意见变为config数据
4. **ProbeKit**：探针断言执行器——把verify_release.ps1/pytest里的散点断言统一为Plan声明的`probes[]`/`verify[]`执行

## 6. 反目标（继承方向验证）

- 不做"通用agent编排"（B路线已否决——那是harness研究的领地）
- 不引入运行时动态加载用户代码的plugin机制（安全面+复杂度；v0.x只支持注册表式stage引用）
- 不牺牲可辩护性：**每个Plan变更过probe集回归**（config也是代码，也会坏）

## 7. 与论文/harness的接口

- 论文artifact evaluation提交物=repo@tag+plans/+probes/（复现=load Plan+run probes）
- 回流harness（跨仓库，另立项）：PlanRunner的"声明式规约→受控执行→门控验收"三元组与contract-driven-harness的TaskSpec/WorkflowGate同构——作为harness论文的检测域案例引用，不在本仓库实现

## 待定问题裁决（盘点后，2026-08-26）

1. **per-register权重表达**：盘点确认W15后formal-zh的真实机制是**OR规则（policy）而非权重切换（routing）**——Plan如实分家：`routing`只承载语言级默认权重；语域条件行为（floor升级/EN降级/校准）全部进`policy`节。不为对称性撒谎。
2. **probes统计语义**：断言支持`{metric, comparator, value, n, interval}`显式声明——如`{fpr_upper_wilson95: {value: 0.31, n: 82}}`；n<100自动拒绝FPR@1%类断言（继承D4纪律）。
3. **Plan与model_pins耦合**：`plan.pins: models/calibration/model_pins.json`强制引用+verify断言"runtime引用的每个模型都在pins中"——Plan漂移到未钉版本=verify FAIL。pins保持发布审计契约身份（非运行时读取），由verify强制执行。
